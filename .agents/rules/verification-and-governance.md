# Standing Verification, Expected-Value & Governance Rules (`#145`)

These rules bind every contributor and agent working toward `FlexMESA v0.1.0` (`notes/SCOPE.md`, tracker `#140`, `DECISIONS #9` & `#17`).

---

## 1. Upstream Truth, Translation Order & Deferred Issues

- **Reference**: MESA release `26.4.1` (tag `26.4.1`, commit `c8c2026`, Zenodo `19722306`) is the sole reference (`#141`, `DECISIONS #22`), recorded in `src/flexmesa/data/bundles.toml` with per-file `SHA-256` manifests (`src/flexmesa/data/bundle_hashes/*.sha256.tsv`). All bundled test inputs, module goldens, exact IEEE-754 hexadecimal module test outputs, and stored trajectory histories come from MESA `26.4.1`.
- **Operation-Order Translation & Three Fidelity Levels (`#165`, `DECISIONS #23`)**: Port upstream's algorithm in upstream's order of operations; cite upstream `<module>/private/<file>.f90:<line>` for every behavioural change. Do not write a simplified stand-in under the upstream routine's name, do not rearrange formulas on the strict numerical path, and never call platform transcendentals or `mul_add` directly in physics crates (enforced via workspace `clippy.toml` `disallowed-methods` and `crates/flexmesa-math/tests/routing_governance.rs`). All workspace crates enforce `#![forbid(unsafe_code)]` except `flexmesa-crlibm-sys`, the sole `unsafe` FFI wrapper around vendored `crlibm 1.0beta4` (`#![deny(unsafe_op_in_unsafe_fn)]`, safe public API only). Only `strict` mode (default) is judged against MESA across three levels: (1) `strict` bit-identical across machines and thread counts on two CI runner types; (2) `strict` kernels bit-identical to MESA against exact hexadecimal outputs wherever operation order matches; and (3) full trajectories within `#143` history tolerances, driving the first diverging step toward zero (`fast` mode is validated against `strict`).
- **No Departures or Option Flags (`#145`, `#169`)**: Reproduce upstream behaviour including upstream bugs, with zero algorithm option flags (the numerics mode is the only run-level switch). For any upstream bug or improvement, open an issue under `#169` with the "Deferred" issue template (`file:line` at tag `26.4.1`, mechanism, effect, proposed change), labelled `deferred` plus exactly one kind label with its title prefix (`upstream-bug` and `[Deferred bug]`, or `enhancement` and `[Deferred enhancement]`); add `parity-pending` while `FlexMESA` code still departs there and `needs-confirmation` until the upstream lines are read at the tag; add its row to the register in `#169` and cite the issue number at the reproduced line. Revert any existing non-upstream "fixes" or departures already in the codebase back to upstream behaviour (`#175`–`#178`). If upstream cannot be reproduced exactly, stop and ask the project lead.
- **Test-Driven Port Order & Loud Errors (`#147`)**: Derive port order from what the next test cases need via `#147`, never from what is easiest. Unknown namelist controls, unrecognised option strings, and missing files or tables must return explicit errors, never silent defaults or synthesized models.
- **Canonical Rust & Frozen JAX Engine Twins (`#166`)**: Rust is canonical; JAX is derived and validated against Rust `strict` mode, never an upstream parity oracle. Do not edit the frozen JAX `star`, `binary`, or `astero` engine files. The one exception is a default argument value that mirrors a Rust control default: when the Rust default changes to match MESA `26.4.1`, the same value may be changed in a frozen file in the same pull request, together with any test literal that repeats it. Algorithms, formulas, signatures and anything else in those files stay frozen.

## 2. Pass Criteria, Expected Values & Known Gaps

- **Definition of Passing (`"green"`)**: An upstream case counts as passing only when upstream's unmodified inlists (with only upstream's per-case `run_*_extras` logic) evolve uncapped to upstream's termination condition and match a stored real-MESA `26.4.1` history within manifest tolerances (`#143`). Step-capped runs or runs without a `26.4.1` history comparison are reported strictly as `"smoke: N steps"` (or `"no reference yet"` when the reference history is absent). A run that continued past unsupported controls (`--allow-unsupported-controls`) is reported as `"diagnostic (N controls ignored)"` and never counts as passing (`DECISIONS #26`). Uncapped strict harness runs are also compared with the committed baseline run, a regression snapshot, and the gate fails when a case stops taking steps, loses upstream's termination condition or leaves tolerance; a deliberate regression updates the baseline in the same pull request and says why (`DECISIONS #27`).
- **Baseline Reuse, Isolated Wheel Runs & CI Timeout Headroom**: Reuse `benchmarks/history_harness/baseline_run_26_4_1.json` as the `before` snapshot whenever `main` has zero un-baselined engine commits; when a fresh `before` run is required, build a non-editable wheel from a detached `main` worktree so active development environments stay intact while heavy campaigns execute serially. Maintain CI `timeout-minutes` headroom at `>= 45` minutes for Rust/E2E suites and `>= 75` minutes for `cargo llvm-cov` so post-step cache uploads complete reliably.
- **Zero Pass-Manufacturing**: Never make a test or case pass by loosening a tolerance, changing an expected value, capping steps, adding `#[ignore]` or `xfail`, clamping state, adding convergence fallbacks, or branching on test-case names or mass ranges. Library crates must contain zero test-case names (`#148`).
- **Declared Known-Gaps Gate (`#144`)**: A case that fails because physics is not yet ported is a valid result; declare every failing case (`[[gaps]]`) and code-level test suppressor (`[[test_gaps]]`) in the single ledger `benchmarks/history_harness/known_gaps.toml` with an open `#<issue>` link. Merge and scheduled gates fail on any undeclared failure, stale gap (a declared gap that begins passing), closed-issue citation, or missing test input (`FLEXMESA_REQUIRE_ZERO_SKIPS=1` defaults active across Python and Rust). Every `#[ignore]` or `xfail(strict=True)` must link an open issue and match `benchmarks/history_harness/known_gaps.toml`.
- **Expected-Value Provenance & Regression Snapshots**: Every change to a pinned numeric literal must record the old value, the new value, and the independent source of the new value in the commit body. Self-generated `FlexMESA` numbers are named `"regression snapshots"`, kept separate from upstream MESA references, and never called `"golden"`, `"reference"`, `"parity"`, or `"Fortran"` (`#146`).

## 3. Debugging Discipline, Scorecards & Reporting

- **Checkpoint-First Debugging & Three-Fix Stop**: Never re-run a multi-minute evolution campaign from step 1 repeatedly to debug a mid-run failure; save a checkpoint a few steps before the failure to replay the transition in seconds (`#150`). If three targeted fixes on the replay fail or expose cross-module coupling, stop and record the root-cause analysis on the GitHub issue before attempting a fourth fix. Keep unconfirmed physical or numerical hypotheses out of rule files until verified against a real-MESA run.
- **Generated Scorecards & Evidence-Gated Manifests**: Status tables, case tables, and dashboard numbers (`#174`) are generated by script, never hand-typed. Do not write completion claims into `notes/`; the pre-audit `PLAN.md` and `LOG.md` are archived in `notes/archive/` and are not edited. Raise a file's status in the port manifest only in a pull request that adds the supporting evidence.
- **Vocabulary & Handoff**: Never write `"verified"`, `"parity"`, `"golden"`, `"green"`, or `"complete"` about anything not measured against real MESA `26.4.1` in that pull request; state plainly what was **not** verified. Close a work package on evidence (`DECISIONS #21`): the authoring agent closes its own issue with a comment linking each acceptance criterion to a CI run, a committed script-generated artifact or a `file:line`, with every MESA-agreement criterion evidenced by a generated comparison against real MESA `26.4.1` output whose header records the MESA version; unmet criteria are moved to a named open issue. An unlinked statement is not evidence, and the independent review reopens packages whose evidence does not hold.
- **Line Limits Subordinate to Fidelity**: File length targets (`<= 400` / `600` LOC) are advisory and yield whenever mirroring an upstream Fortran file or routine one-to-one (`N1-30`).
