# Standing Verification, Expected-Value & Governance Rules (`#145`)

These rules bind every contributor and agent working toward `FlexMESA v0.1.0` (`notes/SCOPE.md`, tracker `#140`, `DECISIONS #9` & `#17`).

---

## 1. Upstream Truth, Translation Order & Deferred Issues

- **Reference**: MESA release `26.4.1` (tag `26.4.1`, Zenodo `19722306`) is the sole reference (`#141`). Any comparison against `0b2e6bb` tracks in `notes/audit/upstream_histories/` must be labelled `"interim reference"` and never used for package acceptance.
- **Operation-Order Translation**: Port upstream's algorithm in upstream's order of operations; cite upstream `<module>/private/<file>.f90:<line>` for every behavioural change. Do not write a simplified stand-in under the upstream routine's name, and do not rearrange formulas on the strict numerical path (`#165`).
- **No Departures or Option Flags**: Reproduce upstream behaviour including upstream bugs. Record upstream bugs or improvements as `[Deferred]` issues under `#169` with `file:line` and mechanism; if upstream cannot be reproduced exactly, stop and ask the project lead.
- **Loud Errors on Unsupported Inputs**: Unknown namelist controls, unrecognised option strings, and missing files or tables must return explicit errors, never silent defaults or synthesized models (`#147`).
- **Frozen JAX Engine Twins**: Do not edit the frozen JAX `star`, `binary`, or `astero` engine files (`#166`).

---

## 2. Pass Criteria, Expected Values & Known Gaps

- **Definition of Passing (`"green"`)**: An upstream case counts as passing only when upstream's unmodified inlists (with only upstream's per-case `run_*_extras` logic) evolve uncapped to upstream's termination condition and match a stored real-MESA `26.4.1` history within manifest tolerances (`#143`). Step-capped runs or runs without a `26.4.1` history comparison are reported strictly as `"smoke: N steps"` (or `"no reference yet"` when the reference history is absent).
- **Zero Pass-Manufacturing**: Never make a test or case pass by loosening a tolerance, changing an expected value, capping steps, adding `#[ignore]` or `xfail`, clamping state, adding convergence fallbacks, or branching on test-case names or mass ranges. Library crates must contain zero test-case names (`#148`).
- **No Undeclared Failures**: A case that fails because physics is not yet ported is a valid result; declare it in the known-gaps manifest with an open `#<issue>` link (`#144`). Every `#[ignore]` or `xfail(strict=True)` must link an open issue.
- **Expected-Value Provenance & Regression Snapshots**: Every change to a pinned numeric literal must record the old value, the new value, and the independent source of the new value in the commit body. Self-generated `FlexMESA` numbers are named `"regression snapshots"`, kept separate from upstream MESA references, and never called `"golden"`, `"reference"`, `"parity"`, or `"Fortran"` (`#146`).

---

## 3. Debugging Discipline, Scorecards & Reporting

- **Checkpoint-First Debugging & Three-Fix Stop**: Never re-run a multi-minute evolution campaign from step 1 repeatedly to debug a mid-run failure; save a checkpoint a few steps before the failure to replay the transition in seconds (`#150`). If three targeted fixes on the replay fail or expose cross-module coupling, stop and record the root-cause analysis on the GitHub issue before attempting a fourth fix. Keep unconfirmed physical or numerical hypotheses out of rule files until verified against a real-MESA run.
- **Generated Scorecards & Evidence-Gated Manifests**: Status tables, case tables, and dashboard numbers (`#174`) are generated by script, never hand-typed. Do not edit `notes/PLAN.md` or `notes/LOG.md` to record success. Raise a file's status in the port manifest only in a pull request that adds the supporting evidence.
- **Vocabulary & Handoff**: Never write `"verified"`, `"parity"`, `"golden"`, `"green"`, or `"complete"` about anything not measured against real MESA `26.4.1` in that pull request; state plainly what was **not** verified. Mark finished work packages `"ready for verification"`, never complete on self-report.
- **Line Limits Subordinate to Fidelity**: File length targets (`<= 400` / `600` LOC) are advisory and yield whenever mirroring an upstream Fortran file or routine one-to-one (`N1-30`).
